# 🌐 Info de DNS y Networking en PaaSify

Antes de crear un servicio, es importante que entiendas cómo PaaSify gestiona la conectividad de los contenedores para maximizar tanto la accesibilidad como la seguridad de tus proyectos.

PaaSify implementa un sistema inteligente de conectividad web y DNS dinámico, apoyado por **Traefik**, que te ayuda a no tener que preocuparte por configurar manuales dominios y SSL.

---

### 1. Acceso Dual (Subdominio y Puerto)
Si despliegas un **servicio web** (ya sea seleccionando una imagen del catálogo, subiendo un Dockerfile, o mediante docker-compose), PaaSify te proporciona dos formas de acceder a tu contenedor a través de su interfaz de usuario:

#### 🌍 Botón de Acceso DNS (Predeterminado)
- **Representado por el icono del Mundo.**
- Utiliza la red dinámica de **Traefik**.
- Ideal para entornos de producción y para probar subdominios: `http://mi-app-305.localhost`.
- **Nota:** Requiere que el contenedor esté en la red `traefik-net` (PaaSify lo hace por ti).

#### 🔌 Botón de Acceso Directo (Puerto)
- **Representado por el icono de Red/Conector.**
- Utiliza el mapeo directo de puertos de Docker: `http://<host>:<puerto_mapeado>`.
- Útil como respaldo si el subdominio DNS presenta problemas de configuración de cabeceras (como en servidores Nginx mal configurados).
- **Importante:** Este botón solo aparecerá si el servicio tiene un puerto externo asignado.

> [!TIP]
> En la interfaz web de PaaSify siempre verás estos dos botones bajo la cabecera **URL de Acceso** para tus contenedores en ejecución. Si el contenedor no es web o está detenido, estos botones se ocultarán automáticamente por seguridad.

---

### 2. Seguridad y Aislamiento en `docker-compose`
Cuando haces un despliegue múltiple usando un archivo estructurado `docker-compose.yml`, se aplican fuertes medidas de seguridad automáticas:

**No todos los contenedores reciben acceso web ni puerto público.** 

- PaaSify analiza el código del YAML y **solo** expone y asigna DNS a los contenedores que **exportan puertos expresamente** (ej: `ports: - 8080`).
- Los contenedores internos (ej: bases de datos como `db`, `mysql`, o colas de mensajes como `redis`) que no mapean puertos se mantienen **completamente ocultos, aislados y seguros de Internet**. 
- Estos contenedores seguros no reciben subdominio y solo sus contenedores "compañeros" dentro de la misma red interna pueden conectar con ellos.

**💡 Nota de Routing para Compose:**
Los valores de puerto en los ficheros YAML de tu Compose no necesitan ser exactamente el 80 o el 443; PaaSify autogestionará todo el enrutamiento de peticiones sin importar el puerto interno.
